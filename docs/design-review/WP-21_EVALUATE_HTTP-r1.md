A consistent client declaration cannot prove the content of untransmitted stdin.

The durable application requires SQLite. `storage_not_enabled` is an explicit 409 rejection here; V1 window storage remains supported. New records share existing device/event identity. Same-protocol exact retries use historical metadata/rewrite-only regeneration; V1/V2 cross-protocol retries are an explicit 409. Stopped/out-of-scope decisions remain private. Receipts never rewrite immutable decision/enforcement metadata returned by duplicate evaluation. Unknown append acknowledgement stays a 503 unknown outcome, with no source/error text reflection.

## Real wire and renderer

The response is `v:2`, `kind:canonical_evaluate_response`, separately named from the prior placeholder CanonicalDecision candidate. It binds the complete retained event via `requestHash` under the accepted canonical hash scheme (uploadSize remains excluded). It contains server policy/catalog/engine metadata, immutable first-decision fields and actual compact composite edits. Detector trace omission is explicit: unique-kinds-only engine summary and full-trace-omitted rendered summary are not complete findings.

The compact `rendered_composite_payload` retains complete actual edits, source/effective-view hashes, renderer revision, residue/persona completion and a hash/count summary of omitted observations/findings. It is not a detector-span union, an empty-patch rewrite, or stronger URL/shell validation than the existing algorithm. Replacements may contain untouched source, so neither replacements nor updated values are saved to replay storage. Metadata-only historical witnesses remain authoritative.

`applyCanonicalEvaluateResponse` validates response closure, request/event binding, explanation consistency, summary/trace agreement and complete rewrite edit/source/result hashes before returning executable updatedInput to the existing host formatter. It must receive the exact event retained by the trusted local producer. Omitted detector execution cannot be reverified from the compact payload. Display text is never used as updatedInput. Real-server integration compares resulting bytes with all 13 actual offline `runHook` outputs and V1 HTTP rewrites.

The application serializes and checks the entire response before publishing session effects or appending. The route sends those checked bytes directly with the existing security/cache/content-length headers and metrics, avoiding an additional parse/stringify. This does not change the documented non-atomic session publication/SQLite failure boundary. Implementation binding revisions are incremented for this candidate; unavailable old executable semantics still refuse replay rather than re-evaluating an old decision.
